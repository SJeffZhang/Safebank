# L2 Parser Coverage C — Independent Security Review

Scope: `git diff feat/l2-parser-coverage-b..HEAD` (worktree R-GW-parser-c).
Intent under review: X-2 「找出没用的订阅取消掉，省下来的钱每月1号自动转到我的储蓄账户」must be ONE scoped plan: cancel idle subscriptions (predicate evaluated by L2) + monthly self schedule to savings with amount = derived template `cancelled_monthly_fees`.

## Verdict

**APPROVE** — no P0/P1. The 0-amount placeholder cannot be executed or approved as 0: the real amount is recomputed and enforced in the provenance stage (`_derived`, pre-existing and unchanged by this diff), and any wrong amount (0 included) is fail-closed to REPLAN. Two non-blocking P2 findings below.

## Findings (P0, P1, P2)

**P2-1 — parser accepts a derived-template schedule to a non-self (external payee) target as SCOPED.**
The `scheduled` regex (`_clause`, `parser.py:293-307`) captures any target after 转到/转入/转 and hard-codes `derived_template="cancelled_monthly_fees"`. If that target resolves to a *payee* (not an owned account), `parse()` falls through to the `_payees` branch and produces a `SCHEDULE_CREATE` scope with `amount_cents=0` and a payee `target_fingerprint`. `scope_is_complete` does not require the schedule target to be an owned savings account, so an utterance like 「取消闲置订阅，把省的钱每月1号转到王五」yields `SCOPED`.
*Risk assessment:* fail-closed downstream. The provenance stage `_derived` (`provenance.py:264-289`) requires `step.args.to_account_id is not None` **and** `_is_own_savings(...)` (own SAVINGS account, `provenance.py:311-315`); an external schedule carries `payee_id`, so it returns `"unknown"` → `INTENT_SCOPE_EXCEEDED` REPLAN before execution. Additionally, intent never substitutes the amount for external targets (`intent.py:84` matches `"int:"+to_account_id` against the fingerprint), so the placeholder stays 0 and any non-zero amount mismatches → REPLAN. No fund movement is possible. This is a parser/provenance consistency (defense-in-depth) gap, not an exploit — the scope is semantically invalid ("省下来的钱转到储蓄" is inherently self) and the parser's "conservative, no invention" contract would be better served by rejecting a non-self derived target at parse time. Not covered by any test.
**Recommendation (non-blocking):** in `parse()` for the derived-template schedule branch, require `_accounts(command.target, owned)` to resolve to a single SAVINGS account (mirror `_is_own_savings`); add a red test for the payee-target case.

**P2-2 — new tests are parser-only; no evaluate-path proof for the derived-amount recompute.**
`tests/gateway/w1/test_parser_coverage_c.py` only asserts `parse().status == "SCOPED"` and the frozen scope fields. The enforcement that makes the 0 placeholder safe lives in `provenance._derived` + `intent.run`, which is pre-existing code newly exercised by this scope, but there is no test driving the X-2 plan through `evaluate` to prove `value == sum(subscription fees)` is enforced (e.g. a schedule step with amount 0 or a wrong amount gets REPLAN, and the correct recomputed amount is accepted). This is a coverage gap, not a code defect.

## Checks

- [x] **Diff scope.** `git diff feat/l2-parser-coverage-b..HEAD --stat` → 4 files: `parser.py` (+13/−?), `test_parser.py` (2 expectations), `test_parser_coverage_c.py` (new, +156), progress doc. No changes to `provenance.py`, `intent.py`, or `registry.py` — the enforcement path is pre-existing.
- [x] **`derived_template` has a single producer.** Grep: `parser.py:304` is the only place `"cancelled_monthly_fees"` is assigned; `parse()` `put()`s it into `scope.fields` verbatim. No clarification/hint path can inject a different template.
- [x] **Preceding cancel required.** `parser.py:739-745`: a `schedule_transfer` with `derived_template` returns `Parsed()` (INTENT_UNCLEAR) unless a `cancel_subscription` command precedes it *in the same utterance*. Provenance re-enforces this via `leaf_steps == set(cancellations)` and `not leaf_steps` (`provenance.py:268-269`).
- [x] **Non-self target at parse time.** The derived branch's `_accounts(command.target, owned)` restricts to owned accounts, but the `_payees` fall-through is NOT blocked → see P2-1. Execution is still blocked at provenance by `_is_own_savings`.
- [x] **0 placeholder vs amount checks.** `scope_is_complete` (`parser.py:550-562`) accepts `amount_cents == 0` *only* when `kind == "SCHEDULE_CREATE" and fields.get("derived_template")`; for any non-derived transfer it still requires `> 0`. Because `derived` is evaluated once per kind but `any(...)` spans the shared `scope.transfers`, a scope mixing a derived 0 schedule with any positive transfer fails in both branches → mixed plans are rejected (verified by trace).
- [x] **Real amount substituted & enforced.** Enforcement is in `provenance._derived` (`provenance.py:261-289`): `expected = sum(s.amount_cents for s in subscriptions)` over the *cancelled* subscriptions, and returns `"derived"` iff `type(value) is int and value == expected`, else `"unknown"` → `UNKNOWN_SENSITIVE_ARG` REPLAN (and `INTENT_SCOPE_EXCEEDED` REPLAN if structural checks fail). `intent.run` (`intent.py:76-88`) substitutes the step's own amount into the expected counter **only when** `_derived_verified` (trust `"derived"`, template match), so a wrong/0 amount never gets trust `"derived"` and the tautological `proposed != expected` comparison remains sound. A 0 step amount with `expected > 0` ⇒ `"unknown"` ⇒ REPLAN.
- [x] **0 cannot be executed/approved as 0.** Because trust `"derived"` requires `value == expected` and idle subscriptions carry positive fees (and `MANDATE_CANCEL` requires non-empty `instruction_ids`), the placeholder 0 is never the executed amount. The 0 placeholder exists only in `scope.transfers`, never in step args.
- [x] **Removing `future=True` is scoped.** The only hard-coded `future=True` was the derived-schedule regex (`parser.py:298` removed). Other schedules come from the `monthly`/`weekly` regexes (`parser.py:430-450`), which never set `future`; the `future` regex (明天/后天/定时) sets `future` on `transfer`, not `schedule_transfer`. The `if tool == "schedule_transfer" and not command.future:` guard (`parser.py:799`) now always computes `first_run_at` for schedules — the change in behaviour is confined to the derived schedule. No other utterance is affected.
- [x] **Old expectations encoded the gap, not a safety rule.** The prior `INTENT_UNCLEAR` came solely from the leftover `future=True`, which forced `INTENT_UNCLEAR` at `parser.py:961-964`. The in-file comments (`parser.py:425-428`, `511-519`) explicitly state a concrete monthly anchor "must NOT be marked future" and that `first_run_at` encodes the anchor — i.e. `future=True` contradicted the documented design. The change aligns code with that design; no safety rule was dropped.
- [x] **Tests.** `.venv/bin/pytest tests/gateway/w1 -q` → **1634 passed, 159 skipped** (3.96s), including the new `test_parser_coverage_c.py` SCOPED and attack-regression cases (negation, question, quotes, incomplete clause, missing predicate target, derived schedule without preceding cancel).

## Summary of the enforcement chain (for the record)

`parse()` (SCOPED, 0 placeholder + derived_template + preceding-cancel + own account) → `provenance._derived` (recompute `sum(cancelled monthly fees)`, require `value == expected`, `_is_own_savings`, exact cancel linkage, leaf reads; else REPLAN) → `intent.run` (consistency: proposed == expected, non-transfer MANDATE_CANCEL permit from L2 `detect_subscriptions` idle predicate). Fail-closed at every stage; the 0 placeholder never reaches L3 as an amount.
