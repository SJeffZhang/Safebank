## 2. 逐项核对（探针输入 → 实际输出）

1. 装饰符剥离：`🎉给王五转800元🎉` → SCOPED 王五 80000；`给王🎉五转800元`、`给王五转8🎉00元`、`给王五转八🎉〇〇元`、`给王五©转800元`、`给王五转8️⃣00元`（keycap 保留→失败）均 INTENT_UNCLEAR；`给王五转800元👍🏻`、`🇨🇳`、`©` 在非同类字符之间被去除且不改变目标/金额。ZWJ/VS16 夹在两汉字间→None。账号/手机号：两数字间的装饰符一律 fail closed；解析器账号语法要求连续 `\d{8,}`、手机号要求整 11 位，故剥离不会拼出原文中不连续的号码，`echoes_untrusted`（作用于原文）未被绕过。通过。
2. 无逗号多笔：`给王五转800元给赵六转900元`、`…再给…`、`给王五800元给赵六900元` → 两笔正确配对；`王五800元给赵六900元`（首段裸）、`给王五转800元给赵六`、`转800元给王五转900元给赵六`、`从储蓄给王五转800元给赵六转900元` 均 INTENT_UNCLEAR。每段独立 fullmatch，错配需要姓名内含完整金额且相邻中文数字守卫生效，未找到错配实例。通过（见 P2-3）。

## 3. 发现（P0/P1/P2）

**P0：无。** 未发现任何输入使 SCOPED 结果出现用户未明确说出的收款目标、金额、卡、订阅集合；所有新识别路径的未知/残缺分支均 fail closed。

**P1：无。**

**P2-1 备注吞并其后的指令/否定，用户的后续意图被静默降级为备注文本。**
- `给王五转800元，备注房租，再给赵六转900元` → SCOPED，只有 王五 80000，memo='房租,再给赵六转900元'。
- `给王五转800元 附言：给赵六转9000元` → memo='给赵六转9000元'；`给王五转800元，备注房租，取消所有订阅` → memo='房租,取消所有订阅'；`给王五转800元，备注不要转了` → memo='不要转了'。
- 影响：授权只会更窄（第二指令不被授权，L1 若计划之会被 INTENT_SCOPE_EXCEEDED 拒绝），资金不会错误移动；但确认面板会出现一条看似指令的备注，用户可能误以为第二笔/取消已处理，且“不要转了”这类撤回语义被当作备注而照常授权转账。建议：备注内出现分句分隔符后跟可识别写指令，或含否定/撤回词时 fail closed（或至少要求备注为最后一个分句且不含 `，;` 后续分句）。

**P2-2 备注内容与用户原文不一致导致下游必然 REPLAN（体验缺陷，安全上 fail closed）。**
- 引号被先行剥离：`给王五转800元，备注房租“押金”` → memo='房租'（原文为 房租“押金”）；`备注“房租”` → INTENT_UNCLEAR。
- 装饰符被剥离：`备注房租🎉` 的 memo 不含 🎉；`备注房🎉租` 整句失败。
- 范围不一致：`明天给王五转800元，备注房租` 接受 memo（future transfer 仍为 transfer），`每月5号给王五转800元，备注房租` 拒绝。
- 影响：LLM 照原文抄写的 memo 与 scope 不等，intent.py:150 拒绝；无授权扩大。

**P2-3 分割边界只看前一字符是否为 元块毛角分钱，含这些字的姓名会使无逗号多笔失败。**
- 构造收款人“钱向东”：`给钱向东转900元` → SCOPED 正常；`给王五转800元给钱向东转900元` → INTENT_UNCLEAR（在“钱|向”处多切一刀，回退整句也不合法）；加逗号则正常。
- 影响：仅 fail closed，属识别率小回归边界；建议边界前一段必须以完整 MONEY 结尾（例如对每个候选切点要求左段 fullmatch 某转账语法后再切）。

**P2-4 装饰符“同类相邻”判定的 CJK 范围仅 U+4E00–U+9FFF。**
- `〇`(U+3007)、扩展 A 区汉字被视为非 CJK，夹在其与常用汉字间的装饰符会被去除（如 `八🎉〇〇元` 拼为 `八〇〇元`，当前因金额语法不收 〇 而仍失败）。未找到可利用实例，建议把 〇 与扩展区纳入 cjk 判定以符合注释意图。

**观察（非本次引入）**：`给王五转800元给王五转800元` 与逗号版 `给王五转800元，给王五转800元` 一样产生两笔同额转账，行为与既有逗号语法一致。

## 4. 结论

新增识别均建立在“整段 fullmatch + 失败即整体 INTENT_UNCLEAR”之上，下游 memo 等值、span money_cents、echoes_untrusted 原文检查口径一致；未发现授权绕过或资金错误移动。4 条 P2 建议后续修正（P2-1 优先）。
