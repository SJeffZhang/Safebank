## A 当前结论

可以演示多项真实银行业务，但现在不能宣称“全部功能已跑通”或“六场景完整验收通过”。

本轮在内置浏览器操作真实三层服务，未使用合成预览页。源码为 `22a87799c2b422a6c2186490a5972e11bc05dce4`，代际为 `demo_20261101050549_93b880b1`。所有客户、资金与持仓均为本机沙箱合成数据。

主工作区仍为旧提交，产品代码未改。本轮部署与源码核对使用独立的 `safebank-freeze-live/WeBank` 工作区。旧演示库、卷和答辩高清素材继续保留。

## C 已复现的主要故障

| 优先处理 | 现象 | 已核对的原因与影响 |
|---|---|---|
| 完成回复金额错误 | 输入、审批和实际转账均为100元，助手却说5000元。 | 完成回复由LLM生成；数字验证把余额、限额和执行数字混在同一事实集合，没有绑定转账金额语义。没有发生5000元转账。 |
| 新风险测评走不通 | 六题均选择保守型测试答案，点击提交预演返回DEPENDENCY_UNAVAILABLE。 | L2确认面板对submit_risk_assessment保留fail-closed分支，直接抛异常并转503。SQL仍无测评、风险等级null。 |
| 连续对话错误拒绝 | 同一会话先查9月账单，再要求取消闲置订阅并每月储蓄，返回REPLAN。 | G4把旧NO_WRITE账单原话混入授权根，集合不一致使授权证据清空。X2计划、派生199元及日历来源本身正确；未发生取消或定时创建。 |
| 账单展示上下文错误 | 请求9月或上月，对话内嵌账单仍默认10月。 | 可见结果与请求月份不一致。独立月报文字与SQL两月合计相符，不能用文字正确掩盖UI错误。 |
| 产品类型映射错误 | 安心货币、成长股票都显示“混合产品”。 | 后端枚举为MMF/BOND/MIXED/EQUITY，前端识别旧值MONEY_MARKET，其余默认混合。 |
| 状态展示未收口 | 操作完成后旧“等待您确认”卡仍留在对话；完成弹窗顶部仍显示待确认。 | 页面同时存在已完成与旧待确认内容，容易让观众误判。 |

## D 需求里仍缺少的链路

源码核对发现：通知模块目前只生产APPROVAL_PENDING、EXECUTION_RESULT。PRD要求的未来扣费提醒、拒扣通知、定时结果及基金结果通知没有完整客户通知生产链路。

AA付款进度依赖的D4外部事件入口仍返回503占位。L3已有付款事件规则，不能据此宣称浏览器演示链路完整。支持的命令行demo-reset确实可用，不能把D1接口占位误写成“无法重置”。

另有手机号自然语言转账的静态覆盖疑点，详见29项矩阵。本轮未对该句式发起现场请求，因此不列为现场失败。

[29项需求逐项核查](requirements-audit.md)区分历史证据、当前实现及尚未验收。矩阵原文是独立静态核查，本页补充本轮UI结果。

## F 验收边界与证据

本轮没有执行两个独立reset后的全部43条生产用例，也没有完成断网make demo。默认make demo仅选择6条固定用例；observe-only的OBSERVED及退出0不代表业务已验证。不能据此冻结demo-v1。

建议先修复完成文案、测评面板、连续会话授权集合，再校准月份与类型展示。通知和付款事件接口应补齐，随后在精确提交上重新运行全清单、时钟事件及离线回放。
