# ADR-014：以确认视图为授权依据，策略只升不降

状态：提议，待团队评审。通过后再改 PRD §7.4–§7.6、§6.2，并升级冻结契约到 v2；评审前现行 PRD 仍有效。

## 背景

现行授权要求两件事同时成立：

1. G3 能把用户原话解析成写作用域（动作、目标、金额、源账户）；
2. 计划里每个敏感参数都能用 `arg_sources` 证明出处（原话字符区间、本会话读取的 JSON 指针、前序步骤或两个派生模板），L2 逐值核对。

两者都过，才进入预演、定级和用户确认。

live 测试中，大部分失败来自这两道门，而不是业务或预演本身。典型现象见 AGENTS §4 10-27 至 11-01 的记录：

- 解析覆盖不到的说法被判 `INTENT_UNCLEAR → FORM_REQUIRED`；
- 模型标错区间或指针，被判 `UNKNOWN_SENSITIVE_ARG`；
- 默认账户、周期、首次日期等参数，原话里没有出处，被判 `INTENT_SCOPE_EXCEEDED` / REPLAN；
- 引用整条读取对象导致误判 `TAINTED_SENSITIVE_ARG`。

每补一种句式或来源规则，就会冒出下一种失败，L1 的结构化输出也因为 `arg_sources` 而变得脆弱。11-01 正式复验 43 条中只有 19 条完全通过。

同时，所有写操作最终都要用户在 L2 生成的面板上确认，并以 `view_hash` 绑定，红级还要 OTP。用户确认的是确切内容，这本身就是授权证据。

参考实现 SayDo（`SuperWheel/saydo-agent@90614fb`）只用一条链路：提议 → 确定性规则定级（只升不降）→ 用户按 digest 确认 → 确认时复核（风险升高即作废）→ 红级验证 → 一次性执行令牌。它没有原话作用域，也没有逐参数来源证明。见 `apps/api/app/auth/actions.py`（`propose_action`、`confirm`、`_revalidate`、`_execute`）、`auth/tokens.py`（digest 与 OTP 绑定）、`policy/rules.yaml`。

## 决定

**写操作是否执行，由「用户对 L2 正式视图的确认 + L2 确定性策略定的等级 + 该等级要求的验证」共同决定。** 规则、模型和真实表单都只是提议方。原话和参数来源不再是授权前提，只作为风险信号。

本决定仍满足约束 #4：LLM 不决定授权，模型的任何输出都不能降低等级或跳过确认。

### 1. 授权链

1. **提议。** 规则快速通道、L1 模型或 App 表单向 G4 提交计划草案，只需工具和参数，`arg_sources` 可省略。
2. **校验与预演。** L2 校验契约，并核对实体归属：账户、卡、收款人、指令、持仓、订单都必须属于该客户。随后用 bankcore 整份预演，跨步骤工作流检查照旧。
3. **定级与拦截。** 策略规则逐条计算，命中就上调等级，只升不降。规则用到的事实（放宽还是收紧、是否新收款人、累计额度、适当性等）由 L2 从快照算出，不采用模型填写的值。硬拒绝时不生成审批。
4. **确认。** 可办计划保存为待确认，确认面板由 L2 生成，展示等级、原因和预演影响。用户确认必须带当前 `view_hash`，红级再完成 OTP，OTP 同样绑定 `view_hash`。
5. **执行前复核。** G6 在同一事务内，用新快照重新预演并重新定级：
   - 风险升高，或出现新的硬拒绝：作废本次审批，提示用户重新发起；
   - 风险不变、只是验证要求变严：补加验证；
   - 视图变化：按现有规则重新确认。
6. **执行。** 复核通过后由 L2 创建作业并驱动 L3，不再经过 L1 恢复。执行屏障、UNKNOWN 对账和幂等沿用 ADR-008 与 §7.10。

所有交互式写操作都要确认，绿级也一样。

### 2. 硬拒绝（不出确认卡）

- 银行硬约束：余额或限额不足、卡状态不允许、适当性不满足、风险测评缺失或过期、超过非柜面单日硬限额；
- 实体不属于该客户，或计划结构非法；
- 熔断：短时间内写操作频率异常、连续 OTP 失败、注入或诈骗嫌疑叠加大额，按配置暂停写操作；
- **值级注入组合**（保留的唯一来源类硬规则）：同一计划既新增收款人、又向该新账号转出，且该账号出现在客户不可信数据中（交易备注、对手方、商户名、定时目标显示名，以及本会话读取结果中的不可信自由文本）。

### 3. 只升级、不拦截的风险信号

- 账号出现在不可信数据中、且不是已有收款人：升红，面板标注「该账号出现在交易备注中」。
- 本轮用户文字含注入或绕过验证的说法：升红，可附冷静期。
- **原话一致性比对。** L2 仍用确定性词典解析原话，但只用于比对，不用于拦截。卡上的目标、金额、源账户与用户说的不一致（例如说「王五」、卡上是「王武」，说 800、卡上是 8000），或用户没说过的参数是推断出来的：至少升黄，面板逐项高亮并注明「小安推断」或「与您所说不同」。
- 疑问句、引号或书名号里的内容：可以出卡，但面板标明「您刚才是在询问」。

现有新收款人、累计转出、放宽卡限制、首笔大额、拆单、理财申购赎回等规则照旧，统一改为升级规则。

### 4. 原话的新角色

- 仍由 G3 登记并保存，供审计、零模型快速通道提取参数和一致性比对使用。
- 取消词仍会使会话 epoch 递增，并作废未确认的审批。
- 不再产生或消费「写作用域」。不再有 `INTENT_UNCLEAR → FORM_REQUIRED` 拦截、作用域频控和 `authorization_claims` 作用域占用。审批数量与频率由熔断规则控制。
- 澄清（G21 候选、同名或近名选择）只是交互：用户选定后生成新的草案，再走同一授权链。

### 5. 定时与持续授权

首次创建、实质变更和取消都要走同一授权链。到期事件按已批准的条款执行；每期执行前重新定级，超过创建时的等级就跳过本期、通知用户并要求重新确认。取消后的墓碑语义沿用 ADR-013。

## 影响

**被取代或改写的 PRD 决议：**

| 决议 | 处理 |
|---|---|
| D9 | 原话不再作为授权来源。typed、hint、action 只用于审计、比对和交互。 |
| D10 | 删除。流出金额只要经过确认即可，不要求来自原话或派生模板。 |
| D11 | 意图范围比对改为一致性比对，只升级、不拦截。 |
| D33 | `arg_sources` 改为可选，仅作诊断。派生模板保留为可选提示，不再是授权要求。 |
| D36 | 只保留值级注入组合与升级部分；引号、疑问句不产生作用域的规则改为面板标注。 |
| D31 | 保留澄清交互，删除「补答合槽产生授权」。 |

D5 中「助手令牌由原话登记签发」需要另定签发方式，见下方待定。D8、D35 的 `view_hash` 确认、ADR-008 执行屏障、三层隔离、bankcore 共用、金额以分为单位全部不变。

**契约。** PlanDraft 的 `arg_sources` 改为可选，`understanding` 可选，升级为 contracts v2；L1 strict Schema 随之变简单。旧计划兼容读取。

**代码。** W1 的作用域解析与匹配、W2 的来源与污点校验改为产出风险信号，大部分拦截分支和对应测试删除或改写；W3 新增升级规则与复核作废；G6 改为直接驱动执行（见 v2.0 重构方案）。

**研究叙事。** 创新点从「参数来源证明」改为「执行前金融预演 + 跨步骤工作流风险 + 绑定确切视图的确认与复核」。评测增加一个「只有确认、没有预演和工作流规则」的对照组，用来证明后两者拦下了用户会误点的攻击，并报告正常任务完成率。

## 未采用的方案

- **维持现状（原话作用域 + 来源证明作为拦截门）**：安全上更严格，但实测完成率不可接受，而且每增加一种说法都要补规则。
- **折中（来源证明保留为大部分拦截，只放宽部分错误码）**：仍然让模型承担来源标注，L1 输出依然脆弱，收益有限。

## 待定

1. 助手令牌签发：改为按会话签发、短期有效、绑定 sid，还是保留按原话登记签发但不再携带授权语义。
2. 熔断阈值与冷静期参数。
3. 一致性比对中，哪些不一致直接升红（例如目标不同），哪些只升黄（例如推断的源账户）。
4. 旧客户端（依赖 FORM_REQUIRED 与 hint 采纳）的兼容期。
