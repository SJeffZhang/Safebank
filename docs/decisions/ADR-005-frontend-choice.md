# ADR-005：竖版 BankSense App 与同站 BFF

日期：2026-10-28。状态：本次前端实现采用，真实三层联调尚未验收。

用户明确恢复前端，并要求直接在主项目 `frontend/` 开发、由 Codex 亲自实现，不使用 DS worker。产品形态为竖版银行 App；视觉风格与配色继承队友 WsTwistzz/safebank-ui，不能改成桌面 Web 工作台。FinMate 仅作组件思路参考，不复制其外观、资产或压缩代码。

保留队友 React 18 + TypeScript + Vite 项目与原 `styles/tokens.css`。375×812 为桌面手机预览容器，小屏铺满；采用内部滚动、底部导航、底部确认面板，主题沿用原 ThemeProvider。原组件/页面仍保留以便核对，新入口与契约适配在 frontend/src/mobile。

同目录以 Node 22 内置 HTTP/fetch 实现 BFF，接口白名单覆盖 F1–F12，console F13 在后端 W5 完成前不冒充可用。令牌只保存在服务端会话内，浏览器持有随机 HttpOnly cookie。POST 同源与自定义头校验、固定上游、禁重定向、同会话串行处理；确认和 OTP 不进入 L1。审批只凭 ID 获取 L2 PlanView，1 秒后且可信用户手势才可确认。所有文字均通过 React 文本节点渲染；写表单没有 URL 或助手内容预填。

## 已核对的实际 wire 差异

`services/agent/app/main.py` 当前 stream 入口读取 input.utterances；输出 messages、values、custom 及 __interrupt__，与 PRD §6.5 目标格式不完全一致。`scripts/try_agent.py` 也采用 utterances。BFF 仅用 G3 返回的原话 id/kind/text 构造 L1 输入；将 messages 规范成 updates.reply，过滤完整内部 values，并在 EOF 前发送最后的中断 updates。未改 L1 授权或后端业务。

L2 的 PlanView.status 实际是 PlanStatus.PENDING_APPROVAL，金额字段为格式化字符串且 unit="元"（gateway/app/approval/planview.py），App 按真实字段展示。预览适配器单独隔离，不代表 L2 授权判定实现。

## 验证与边界

新 App 的协议/组件、BFF 的本地假上游 HTTP 测试及竖版浏览器验收独立记录于前端验收文件。真实后端联调、真实模型、W5 控制台、生产多实例会话及完整 P2 仍未完成。BFF 当前仅单进程内存会话，重启需重新登录；不会将 G18 的只读助手令牌用于计划恢复。

## 2026-10-28 App 交互修正

按用户反馈统一二级页面返回键、App 内历史回退、底部选择面板与月份选择。测评页以服务端现有记录决定完成/过期展示，用户显式点击更新才进入问卷；预演阶段不提前标记测评成功。共享 Modal 通过根容器 portal 保持底部面板定位，并对嵌套选择实行顶层键盘处理。金额展示独立封装币种与数值的同行 baseline 布局。业务授权与接口不变。

## 2026-10-28 查看卡号

用户要求在卡片页查看完整卡号。现有 R6/CardView 仅 last4，L3 未提供完整卡号，保持冻结契约不变。前端增加显式点击的底部面板，预览从独立合成 fixture 查询并标识“合成演示卡号”；不通过 R6 或助手上下文传递。真实模式返回 CARD_NUMBER_UNAVAILABLE，不从尾号推算。将来真实功能需要补充 App 专用鉴权读取接口与后端存储后另行验收。面板关闭/切卡清除展示数据，晚到结果丢弃，支持复制与失败提示。

查看卡号增量：先输入6位PIN，完整号码响应与验密合并；没有先把号码下载到页面再靠显示条件隐藏。预览内模拟PIN=123456及连续5次错误暂停60秒，只作用于合成数据，不宣称生产安全边界。真实接口需后端验证凭证、账户归属与频控后返回号码，本轮保持不可用。每次打开重新验证；密码不持久化，不写入助手上下文。

## 2026-10-29 卡片用途标签

用户要求修改各卡用途，采用个人显示标签实现：预设+自定义名称，按客户和卡片ID保存在浏览器localStorage。界面明确本地保存，不修改银行权限、不改变后端CardView、不进入L1输入。当前后端无用途契约，跨设备持久化留待后续专用接口。此功能是整理标签，不用于授权判定或限制交易用途。

## 2026-10-29 报告、快捷理财与演示新卡

按用户增量：月/年报组合现有消费与交易汇总读接口，不新建后端报告契约；年度截止模拟月份，缺月显式披露，下载本地txt。产品按服务端风险等级作显示筛选和申购前校验，最终授权仍由网关/银行决定，快捷赎回预填现有持仓份额但不执行。新增CARD_APPLY只属于合成preview计划种类，走现有演示审批/OTP后生成模拟账户/卡；真实模式明确未接入开户，禁止将此扩充误认为冻结ActionKind或真实发卡服务。交易解锁复用已有CARD_UNFREEZE/CARD_CONTROL_LOOSEN/限额调整，不能绕过确认、复演或清零用量。订阅现有页面能力按用户指令保留，主动推送未实现。

## 2026-10-29 我的与订阅合并

按用户指示，我的页以真实profile姓名/首字头像替代安全中心页头，默认内嵌订阅；原安全能力移入安全记录分区，业务组件复用不改写。移除独立订阅侧栏项、兼容旧订阅路由，通知/计划查询通过安全分区深链继续可达。不修改API或授权流程。

## 2026-10-29 主题动效与助手布局

用户指定深浅切换从右上角圆形展开，采用浏览器View Transitions+注册的CSS长度变量驱动渐变mask，800ms；不支持或用户减少动画时降级直接切换。对话界面按用户指示删除外部标题介绍，填满公共导航之间的内容区，新会话并入聊天顶栏，消息区独立滚动。无新增运行时依赖或业务接口变动。
