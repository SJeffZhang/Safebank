# SafeBank v2.0 后端对话与办理重构

**待评审 · 2026-11-15 · 源码基线 `e6a9925`**

**目标是先把可用性拉起来：明确的请求少绕模型，追问能接住，写操作在用户确认后可靠完成。** 授权模型改为以用户确认的 L2 视图为依据、策略只升不降，详见 [ADR-014](../decisions/ADR-014-confirmed-view-authorization.md)。三层分工不变：L1 理解、取数、提议；L2 定级、预演、确认、执行；L3 提供可验证的业务状态。评审通过前，现行 [PRD](../../PRD.md) 仍适用。

## 0. 为什么改

现在 L2 的授权要求「原话能解析成作用域」，并且「每个参数都能证明出处」。live 测试中的大部分失败卡在这两道门：

- 解析覆盖不到的说法被判 `FORM_REQUIRED`；
- 模型标错来源，被判 `UNKNOWN_SENSITIVE_ARG`；
- 原话没提的默认参数，被判 `INTENT_SCOPE_EXCEEDED`；
- 引用整条读取对象，被误判为污点。

而写操作最终都要用户在 L2 面板上按 `view_hash` 确认，这本身已经是授权证据。v2.0 参考 SayDo：任何来源都只是提议，用确定性规则定级，用户确认确切内容，确认时复核，然后由服务端直接执行。

## 1. 授权模型（摘要，以 ADR-014 为准）

1. **提议。** 规则、模型或真实表单提交草案，`arg_sources` 可省略。
2. **校验与预演。** L2 校验契约和实体归属，用 bankcore 整份预演，并做跨步骤工作流检查。
3. **定级。** 规则只升不降，所用事实由 L2 从快照算出。只有银行硬约束、归属错误、熔断和「新增收款人后立即转给出现在不可信数据中的账号」这几类硬拒绝；其余风险都只升级等级并在面板说明原因。
4. **确认。** 所有交互式写操作都要确认，绿级也一样。确认带 `view_hash`，红级加 OTP。
5. **复核与执行。** G6 在同一事务内重新预演、重新定级：风险升高就作废审批，验证要求变严就补验证。复核通过后由 L2 创建作业并驱动 L3。

原话仍由 G3 保存，但只用于三件事：审计、零模型参数提取、一致性比对。卡上的目标、金额与用户所说不一致，或参数是推断出来的，就升级等级并逐项高亮，不再以 REPLAN 或 FORM_REQUIRED 拦截。

## 2. 对话怎么改

| 请求 | v2.0 路径 |
|---|---|
| 明确查询 | [只读匹配](../../services/agent/app/llm/_query_reads.py)前移到模型之前，命中整句后经 L2 取数，由程序计算并用模板回答。 |
| 明确办理 | 规则快速通道直接生成草案，不调模型，出卡与模型路径走同一授权链。 |
| 自由对话 | 模型拿到本轮问题、有限的脱敏历史、上轮已验证的查询对象和当轮工具事实。金额与状态重新取数，关键计算由程序完成。 |
| 复杂或组合办理 | 模型提出结构化计划，L2 整份预演并定级；不再要求逐参数来源。 |

**快速通道触发条件**照搬 SayDo `_fast_path`，全部满足才走：

- 没有注入嫌疑；
- 整句和每个分句都是同一个白名单意图（AA 例外：金额、人名常分在几个分句里）；
- 多轮里出现指代（他、她、那笔、刚才、也……）就交给模型；
- 必需参数都能确定：转账要能解析金额和唯一收款人，停代扣要点名商户；
- 有待回答的追问时，只接能唯一确定候选的回答（「同事那个」「尾号 0921 的」），否则交给模型。

**白名单由回归集决定。** 以 11-01 复验的 43 条和第二轮 24 条为基线，凡规则输出与模型路径一致的意图都纳入，目标覆盖六个场景的高频句式，而不只是三个写操作。

**快速通道这一轮要写进历史**，格式与模型调用工具的记录一致（参考 SayDo `_record_workflow`），这样下一轮模型理解「把它锁一下」时，上下文和它自己调过工具一样。

**首个多轮验收**：「未来七天有哪些扣费 → 最大一笔呢 → 扣完还剩多少」。后两轮沿用同一查询窗口；余额与义务按需重查，由程序计算预计剩余可用余额，避免重复扣减已预留的资金。数据不完整或账户不明确时说明缺项。

**产品体验**参考财小全：首页快捷入口直接映射到快速通道必中的句式；回答附证据卡片，标明数据来自哪次读取；调试模式可显示本轮走的是规则还是模型。财小全的写操作是页面内模拟，不借鉴它的安全模型。

## 3. 确认后谁执行

1. **提议与评估。** G4 校验、预演、定级；可办时保存计划和审批，用户通过 G9 看 L2 正式视图。
2. **确认与执行。** G6 验证客户、会话、审批、`view_hash` 和有效期，完成复核后在同一事务记录确认并创建作业，由 L2 驱动 L3。F8 查状态与回执。新协议下不需要 F4 恢复 LangGraph，客户端也不需要另调 G8。
3. **变化与恢复。** 复核风险升高就作废并提示重新发起，视图变化按现有规则重新确认。旧执行尝试按 [ADR-008](../decisions/ADR-008-state-changed-fence.md) 封闭后才能继续；重复请求复用作业，结果不明时只对账。提议、确认、复核和实际提交分别审计。

**定时办理**在首次设立、实质变更和取消时确认。每期执行前重新定级，超过创建时的等级就跳过本期、通知并要求重新确认。取消后撤销授权，旧事件重放不能恢复。

## 4. 首批范围与验收

| 场景 | P0 交付 |
|---|---|
| 转账 | 单笔走快速通道；本人互转、定时和 AA 走模型提议加同一授权链。 |
| 账单 | 常见查询走快速通道，月报、环比、异常分析保留。 |
| 卡片 | 冻结、解冻、挂失、调限额走快速通道，按风险定级。 |
| 订阅 | 列表、未来扣费、停代扣走快速通道；跑通七天扣费三轮追问。 |
| 理财 | 产品查询、持仓、申赎及适当性校验；问卷仍为专用表单。 |
| 联动 | 至少一条真实模型组合计划跑通，L2 整份预演，L3 原子提交。 |

**实施顺序：**

1. G6 确认后直接执行（契约与审计改动最小、体验收益最大）；
2. 授权模型切换：契约 v2，W1/W2 的拦截改为风险信号，新增升级规则和复核作废；
3. 快速通道与多轮上下文；
4. 按回归集扩展白名单，切流，跑六场景回归。

**上线门槛（可用性）：**

- 43 + 24 条回归集的完成率较 11-01 基线明显提升，目标值评审时确定；
- 快速通道命中的请求在传输层证明零模型调用，端到端延迟目标在评审时确定；
- 不再出现由来源证明导致的 REPLAN 或 FORM_REQUIRED。

**上线门槛（安全）：**

- 确认前 L3 无业务变更，确认后余额、卡状态和代扣按计划变化；
- 覆盖三色提示、红级 OTP、硬拒绝、注入改参数、确认篡改与重放、复核升级作废、崩溃恢复、定时竞态；
- 增加「只有确认、没有预演与工作流规则」的对照组，报告两组在攻击集上的拦截差异；
- 未授权写入与重复提交以真实 PostgreSQL 状态判定。

**迁移与回滚：**

- 计划增加执行协议标记，旧结果兼容读取；
- 旧的待确认审批默认重提，旧的在途作业先对账；
- 回滚时可退回旧对话路由或暂停新写办理，已有作业继续恢复。

## 5. 待评审定案

- ADR-014 的待定项：助手令牌签发方式、熔断参数、一致性不一致的升级档位、旧客户端兼容期；
- 历史保留期限与复杂计划预算；
- G6 返回契约与新旧客户端握手；
- 作业认领与迁移窗口；
- 定时重批的生效时间；
- 通过后同步修改 PRD §6.2、§7.4–§7.6、§9.5，以及 D9、D10、D11、D31、D33、D36。
